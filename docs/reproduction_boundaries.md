# Reproduction boundaries

## What is reproduced by this public release

The public verifier recomputes statistics from a field-level allowlisted export of frozen results: historical intervention endpoints; strict source-change/last-change-zero-exit audit counts; three-state candidate discrimination and historical timing strata; P120 original outcomes and the separately declared source-attribution view; and the existing Abjad eight-test outcome counts. Figure data are derived from these same records. No result is newly sampled to agree with the paper.

Anonymous task and episode IDs preserve cross-panel/repeat dependence and within-panel deduplication while omitting Issue text and raw tool traces. Counts retain UNKNOWN instead of converting it to FAIL except for the explicitly separate, case-specific source-attribution view. Hashes tie the export to original frozen source bytes and the release manifest; the extraction audit retains private mapping details outside this repository.

## What is not reproduced

- No Agent is run. No GPU or language-model endpoint is contacted. Publication-time recomputation is not an additional Agent experiment.
- The public script does not execute the historical self-checks, reproduce the 942 task executions, or rerun the private eight-test Abjad scorer. It aggregates already recorded numerical outcomes.
- No private task tests, reference/gold repair, full scoring rows, task snapshot, official/private scoring integration, prompt bundle, API archive, credentials, or complete private repository/history is included.
- Source-state identity is conditional reconstructed workspace identity. It does not prove historical loaded-module bytes or full runtime recovery.
- Raw SHA256 commitments for withheld sources establish what the authors committed to. They cannot establish source content, correctness or trustworthy historical timestamps without those sources and a suitable independent trust mechanism.
- The release neither supplies fresh heldout task generalization nor identifies which SEAL prompt component caused a repair. It does not prove that more tool budget would rescue a committed artifact.

## Observational and counterfactual layers

Historical stdout/exit feedback, later check reexecution, intermediate-source scoring, and patch ablation are separate layers. A later replay result is not evidence the historical Agent observed or trusted that output. Print-only checks can still carry informative stdout; useful tests can target old source; finite behavior coverage can coexist with a failing final patch.

Original P120 has 71 strict-valid score receipts plus one UNKNOWN. Later candidate-source attribution adds a separate FAIL decision; it does not create an additional valid original scoring receipt. Abjad original C belongs to the 72-Agent campaign. Its DEFAULT_ONLY and FILTER_ONLY variants are two later CPU scoring executions. Current public numerical recomputation adds **zero** Agent generations and **zero** task-scoring executions.

## Minimal public Abjad exception

Three short patches against public MIT-licensed Abjad source are included with exact upstream copyright/license notice. They can be inspected or manually applied by a reader. This source-level availability does not grant access to the excluded frozen task snapshot or private scoring integration, nor make applying them in a different environment equivalent to reproducing the recorded eight-test evaluation.

Original A/B full patches, scratch scripts, raw traces and test bodies are not needed for the code-ablation conclusion and are excluded. Their production changes and score/patch hashes are summarized. The source commitments, dependency version list and outcome projections allow inspection of the reported claims without disclosing the broader task data.

## Review and claims

Semantic review is targeted assistant inspection with provenance checks, not independent human annotation; human signatures remain zero. The full 72-trajectory P120 semantic review is incomplete. The paper's main contribution is a cross-intervention evidence audit and identification of repair-chain breaks. SEAL is an exploratory intervention with one reused-DEV win and unfulfilled final-verification/commitment mechanisms.
